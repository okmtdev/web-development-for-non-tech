# 演習4：検索を追加して、基本操作も確かめる

[第4回教材](../lessons/04-improve.md) / [実装例](../solutions/04-search.md)

前提：アプリが起動できること。最終機能の検索は初期サンプルにはありません。変更するのは `index.html` と `app.js` の2つです。

## A. 目的と合格条件（10分）

次の4件を新しく追加します。既存タスクが多ければ、練習用データだけを確認しながら削除します。

| 名前 | 状態 |
| --- | --- |
| HTMLを読む | 未完了 |
| APIを試す | 未完了 |
| APIを説明する | 完了 |
| DBを確認する | 未完了 |

「APIを説明する」は左のチェックで完了にします。第4回教材の受け入れ条件を読みます。

## B. 依頼と変更（10分＋25分）

1. 2ファイルを授業用フォルダへコピーして退避。Gitが使える場合は作業ブランチを作っても構いません。公開先へpushは不要です。
2. [第4回教材](../lessons/04-improve.md)の依頼文と対象コードをAIへ渡す。
3. 提案された変更箇所を読んで説明する。「検索欄」「入力時のイベント」「状態と検索の両方を判定」の3点があるか確認。
4. 変更を保存し、ブラウザを再読み込み。Supabase版は再ログイン。
5. 検索欄に `API` と入力し、2件に絞られることを確認。

AIを利用できなければ[実装例](../solutions/04-search.md)を手で反映します。どちらの方法でも確認項目は同じです。

## C. 確認と修正（20分）

他のタスクがない状態を前提とした期待値です。

| 入力・操作 | 期待する結果 | 実際 |
| --- | --- | --- |
| すべて、検索は空 | 4件 |  |
| `API` | 2件 |  |
| `api` | 2件 |  |
| ` API ` | 2件 |  |
| `存在しない文字` | 0件、空の状態を説明 |  |
| `API`＋未完了 | 「APIを試す」1件 |  |
| `API`＋完了 | 「APIを説明する」1件 |  |
| 空欄＋すべて | 4件に戻る |  |
| 追加・編集・完了・削除 | 従来どおり操作できる |  |
| 再読み込み | データが残る。検索欄と状態は初期化 |  |

検索中に条件外のタスクを追加すると、保存されても表示されない場合があります。検索を消して「すべて」で確認します。件数表示は保存済み全体の件数で、検索結果の件数ではありません。

エラーが出た場合はConsoleの最初のエラーを読み、変更した2ファイルから確認します。入力のたびに検索欄が消える場合は、一覧の描画処理で検索欄まで作り直していないか確認。状態が無視される場合は、条件がAND（両方）になっているか確認します。

## D. 発表とデプロイ準備確認（15分＋10分）

[評価表](../assessment.md)を埋め、2分でデモをします。続いて `.env` や保存データがGitの対象外か、動作確認が通っているかを確認。続いて[Cloud Runの事前準備](../cloud-run.md)を確認し、第5回の配置対象と残る準備を記録します。GitHubへの公開・反映は別の操作です。
