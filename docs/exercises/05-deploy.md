# 演習5：URLで動かし、保存と再配置を確認する

[第5回教材](../lessons/05-deploy.md) / [具体的なコマンド](../cloud-run.md)

前提：Supabase版と検索機能が動く、練習用A/Bの権限確認が済んでいる、Cloud Run手順の「授業前の準備」を完了していること。講師の管理する環境でペア実習しても構いません。実行するとクラウドにリソースを作成し、費用が発生する場合があります。

## A. 全体構成と公開する内容（10分＋10分）

1. 第5回の構成図を読み、ブラウザ／Cloud Run／Supabaseを指す。
2. `npm run check` と `npm test` を実行。
3. `.env`、タスクファイル、実データを送らない設定を確認。Cloud Run手順の送信対象一覧コマンドを使う。
4. 講師と対象プロジェクト、サービス名、地域、公開範囲、料金、確認したコードを共有してから、操作を始める。

## B. 配置とURL設定（25分）

[Cloud Run手順](../cloud-run.md)の1〜3を順に実行します。新しいサービス名を使い、非公開で配置し、発行されたURLを `APP_ORIGIN` に設定します。ビルド待ちの間は、講師と構成図の通信経路を確認します。

期待する結果：Cloud RunにサービスURLと稼働中のリビジョンが表示される。この段階でブラウザが403でも、まだ非公開なので正常です。失敗したら同じ手順のトラブル表を確認し、完了していない工程を記録します。

## C. 公開と動作確認（20分）

Cloud Run手順4の公開範囲を確認し、学習用ログイン画面を公開します。次の表を実際のURLで埋めます。

| 操作 | 期待する結果 | 実際 |
| --- | --- | --- |
| 発行URLを開く | HTTPSのログイン画面、Supabase接続モード |  |
| 未ログインでURL末尾に `/api/tasks` を付けて開く | 401、ログインを求めるJSON |  |
| Aでログインし「公開後の確認」を追加 | 保存できる |  |
| Aで編集・完了切り替え・検索・削除キャンセル | 変更と絞り込みが動き、キャンセルで残る |  |
| 別ブラウザまたはプライベートウィンドウでAとしてログイン | 同じタスクが見える |  |
| 別の画面でBとしてログイン | Aのタスクは見えない。B自身の追加・削除はできる |  |
| Aで再読み込み、再ログイン | タスクは残り、検索と状態は初期化される |  |

画面で「Bから見えない」ことだけでRLS検証を代用しません。講師は第3回の `npm run test:supabase` でBによる更新・削除拒否も確認しておきます。

## D. 再配置と保存確認（15分）

1. Aの「公開後の確認」を残す。
2. `app/public/index.html` の見出しを「マイタスク 公開版」に変更し、ローカルで表示を確認。
3. Cloud Run手順5の再配置を行う。同じサービス名、同じSupabaseプロジェクトを使う。
4. 公開URLを再読み込み。見出しが変わること、Aで再ログインすると同じタスクが残ることを確認。

期待する結果：コードの変更が公開URLへ反映され、タスクはDBに残る。SQLを流し直したり、DBを作り直したりする操作は不要です。ビルドが時間内に終わらなければ確認を補講へ引き継ぎます。

## E. 構成を説明し、片付ける（10分）

ペアで2分ずつ、画面取得・タスク保存・再読み込み・再配置を構成図で説明します。「ブラウザにも保存できるのに、今回タスクをDBへ置く理由」を含めます。

続いてCloud Run手順6を読み、学習用サービスを残す期限と管理者、または削除する対象を記録します。削除はプロジェクトとサービス名を確認してから行います。

```text
公開したURL：
コードの版・変更した見出し：
画面のJSが動く場所／サーバーのJSが動く場所：
タスクの保存先／ブラウザだけにある状態：
未ログイン・A/B・別ブラウザの確認結果：
再配置後の見出しとタスク：
片付ける対象・期限・担当者：
未達成項目と再確認日：
```

組織の制約で自分の環境に配置できない場合は、許可済みの講師環境で操作を分担します。見学のみの場合は「配置操作」「公開URL確認」を未達成として残し、補講で実施します。
