# 学習の評価と動作確認表

[カリキュラム](curriculum.md)

## 学習者の記録

各項目を「2：自分でできる」「1：助けがあればできる」「0：まだ」で記入します。目標は全項目1以上で、点数の競争には使いません。

| 項目 | 評価 | 根拠・次に試すこと |
| --- | --- | --- |
| 画面・処理・保存の役割を自分の言葉で説明する |  |  |
| 起動・停止し、見出しや色を変える |  |  |
| ブラウザ保存とDB保存の範囲・役割を説明する |  |  |
| APIのメソッド・URL・結果を観察する |  |  |
| 正常入力と不正入力の両方を試す |  |  |
| DBの行と列、認証と認可を説明する |  |  |
| A/Bのデータの分離を確認する |  |  |
| AIへ具体的な変更を依頼し、差分を説明する |  |  |
| 検索追加後に既存機能も確認する |  |  |
| Cloud Runへ配置し、URLで動作を確認する |  |  |
| 配信場所と実行場所、タスクの保存先を構成図で説明する |  |  |
| 別ブラウザ・再配置後のデータを確認し、片付けを計画する |  |  |

Supabaseが利用できなかった場合は、A/B確認を未確認と明記します。ローカルの完成をDB権限検証の代わりにはしません。デプロイを見学しただけの場合も、配置操作と公開URLの確認は未達成として記録します。

## アプリの受け入れ確認

- [ ] 初期の空画面に、次の操作の説明がある
- [ ] 追加・名前編集・完了／未完了・削除が動く
- [ ] 削除キャンセルでデータが残る
- [ ] 状態の絞り込みと未完了件数が一致する
- [ ] 空白だけ／81文字をサーバーが断り、80文字を保存する
- [ ] 再起動しても保存したデータが残る
- [ ] サーバー停止時に失敗が画面でわかる
- [ ] Supabaseで本人以外のデータを扱えない（実DBで別途）
- [ ] 第4回の検索確認表を通過する
- [ ] 第5回の公開URLで、未ログイン401とA/B・別ブラウザを確認する
- [ ] 再配置後に見出しが変わり、DBのタスクが残る
- [ ] 公開リソースの管理期限または削除対象を記録する
- [ ] スマートフォン幅でも操作でき、キーボードでも入力できる
- [ ] `npm test` と `npm run check` が成功する

## 2分の発表

30秒：誰のどんな困りごとを扱ったか。60秒：基本操作と検索のデモ。30秒：変更箇所、確認したこと、未確認のこと。

```text
未確認または未対応：
次に改善したいこと：
```
