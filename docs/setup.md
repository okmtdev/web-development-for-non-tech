# 事前準備（30〜45分）

[教材の入口](../README.md) / [困ったとき](troubleshooting.md)

## 必要なもの

- MacまたはWindowsのPC、ブラウザ（Chrome／Edgeなど）。スマートフォンだけでの受講は対象外です。
- Node.js 24.x LTS：JavaScriptをブラウザの外で実行するためのソフトウェア。
- エディター：コードを編集するアプリ。例としてVS Codeを使います。既存のエディターでも構いません。
- 学習用ファイルを保存できるフォルダ。会社PCではインストール・外部サービス利用の可否を事前に確認します。
- 第3回以降はSupabaseアカウントとネット接続。第5回はGoogle Cloudの請求先・権限・CLIが必要です。講師が管理する許可済み環境での実習も可能。GitHubアカウントは必須ではありません。
- AIチャットまたはコード支援ツール。無料枠の利用可否・上限は契約によるため、授業参加条件に有料APIを含めません。

## 1. Node.jsとエディターを用意する

1. [Node.js公式](https://nodejs.org/en/download)から **24.x LTS** を選んでインストールします。26.xなど別の版ではなく、この教材の検証対象を選びます。
2. 必要なら[VS Code公式](https://code.visualstudio.com/download)からインストールします。
3. エディターやターミナルを開き直します。ターミナルは、文字でPCへ命令する窓です。Macでは「ターミナル」、Windowsでは「PowerShell」を利用できます。VS Codeの「ターミナル → 新しいターミナル」でも開けます。
4. 下の1行を入力してEnterを押します。先頭の `$` などは入力不要です。

   ```sh
   node --version
   ```

期待する結果：`v24.` から始まる数字。見つからない場合はPCを再起動し、[トラブル対応](troubleshooting.md)を確認します。

## 2. 教材フォルダを開く

GitHub反映後はリポジトリの「Code → Download ZIP」で取得し、ZIPを展開します。ZIPの中を直接編集せず、展開したフォルダを使います。反映前は講師から受け取ったフォルダを利用します。

VS Codeで「ファイル → フォルダーを開く」から教材を選びます。`README.md`、`package.json`、`app` が同じ階層に見える状態が正解です。

「ターミナル → 新しいターミナル」を開き、現在のフォルダを確認します。

| 環境 | 確認コマンド | 期待する結果 |
| --- | --- | --- |
| Mac | `pwd`、続けて `ls` | 教材フォルダの場所と `package.json` |
| Windows PowerShell | `Get-Location`、続けて `Get-ChildItem` | 教材フォルダの場所と `package.json` |

別の場所なら `cd "教材フォルダの絶対パス"` で移動します。パスはファイルの住所で、スペースを含む場合は引用符で囲みます。

## 3. 起動・停止する

```sh
npm start
```

`npm` はNode.jsのプロジェクトに定義した操作を実行する道具です。ここでは `package.json` の `start` に書いた処理を動かします。外部パッケージの取得は不要です。

期待する結果：ターミナルに `マイタスク: http://localhost:3000 (demo)`。ブラウザのアドレス欄で **http://localhost:3000** を開きます。`localhost` は自分のPC、`3000` はこのアプリが待ち受ける窓口番号です。

入力欄に「教材を開く」と入れて追加します。1件表示されれば準備完了です。ターミナルを閉じると動かなくなるので、授業中はそのままにします。停止はターミナルで `Ctrl+C`、再開は `npm start` です。

## 4. 設定ファイルは第3回に用意する

`.env` は環境変数（実行時に渡す設定値）を書くファイルです。第1・2回はなくても起動します。作る場合は次のどちらかを使います。

Mac:

```sh
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

すでに `.env` がある場合はコピーせず中身を確認します。`.env.txt` にしないでください。設定を変えた後はサーバーを停止して再起動します。

## 5. AIに渡す情報を分ける

渡してよいもの：教材のコード、架空のタスク、秘密を除いたエラーメッセージ、目標と確認結果。

渡さないもの：パスワード、アクセストークン（ログインを証明する文字列）、`.env` 全体、個人情報、会社の非公開情報。ブラウザの通信画面にもトークンやログイン時のパスワードが表示されるため、スクリーンショットをそのまま送らないでください。

AIを使えない場合は、隣の人と変更案を相談し、[第4回の実装例](solutions/04-search.md)を使います。動作を確かめる作業は同じです。

## 第5回までの追加準備（45〜60分＋承認待ち）

[Cloud Run操作手順](cloud-run.md)の「授業前の準備」を終えます。請求先・利用権限・CLI・APIの有効化は授業中の90分に含めません。準備が間に合わない場合は講師へ伝え、許可済みの環境で操作を分担します。

## 初回の準備完了の確認

- [ ] `node --version` が v24.x
- [ ] `package.json` が見えるフォルダを開いた
- [ ] `npm start` で画面を開けた
- [ ] タスクを追加して、再読み込み後にも残った
- [ ] サーバーの止め方と再開方法がわかった
