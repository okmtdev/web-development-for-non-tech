# 第2回：ボタンを押した後の通信を見る

[カリキュラム](../curriculum.md) / [演習2](../exercises/02-api.md)

前提：第1回を完了し、demoモードで起動できること。90分の流れ：復習10、用語15、通信観察25、入力実験25、コード追跡10、確認5分。

## APIを「窓口」として見る

**API**は、プログラムが決まった方法で依頼する窓口です。今回のURL `/api/tasks` はタスクの窓口。**HTTP**は依頼と応答のルールで、**メソッド**は「何をしたいか」を表します。

| やりたいこと | HTTPメソッド | URL | 成功時の番号 |
| --- | --- | --- | --- |
| 一覧を読む | GET | `/api/tasks` | 200 |
| 新しく作る | POST | `/api/tasks` | 201 |
| 一部を変更 | PATCH | `/api/tasks/タスクのID` | 200 |
| 削除 | DELETE | `/api/tasks/タスクのID` | 204 |

**ID**は同じ名前のタスクも区別する識別番号です。名前を変えてもIDは変わりません。**ステータスコード**は結果の番号で、200番台は成功、400番台は依頼や権限の問題、500番台はサーバー側などの問題を表します。番号だけで原因を決めつけず、メッセージも読みます。

## JSONはデータの書式

追加の依頼は次の形です。

```json
{"title":"教材を開く"}
```

**JSON**は、名前と値を組にして受け渡す書式です。文字列は二重引用符、真偽値は `true`／`false`、複数の項目はカンマで区切ります。`"false"` は文字列で、`false` とは違います。

応答例（実際のID・時刻は毎回異なります）：

```json
{"task":{"id":"12345678-1234-1234-1234-123456789abc","title":"教材を開く","done":false,"created_at":"2026-10-25T00:00:00.000Z"}}
```

## なぜ画面とサーバーの両方で確認するのか

画面の入力欄は80文字で止まります。でも、画面以外のプログラムからAPIへ直接依頼することもできます。**バリデーション**は、入力がルールに合うか確かめること。サーバーでも1〜80文字、空白だけではないこと、`done` が真偽値であることなどを確かめます。

この流れをファイルで追います。

1. `app/public/app.js` の追加処理が `fetch('/api/tasks', ...)` に相当する通信を行う。`fetch` はHTTP通信を行うJavaScriptの機能。
2. `app/server.js` がPOSTを受け取る。
3. `app/lib/validation.js` が `title` を確認。
4. `app/lib/demo-store.js` が保存。
5. 返ったタスクを `app.js` が画面へ追加。

## 演習と確認

[演習2](../exercises/02-api.md)で通信を観察し、空白・80文字・81文字を試します。合格条件は「見た結果を、URL・メソッド・ステータスで説明できること」です。

確認問題：空文字の追加はなぜ201ではなく400か。削除成功が204で本文なしなのはなぜか。画面だけの文字数制限で十分か。解答例は[こちら](../solutions/01-03.md)。
