# 第4回：AIと改善し、動いた根拠を説明する

[カリキュラム](../curriculum.md) / [演習4](../exercises/04-search.md)

前提：基本操作が動くこと。demo／supabaseのどちらでも演習できます。90分の流れ：要件10、AIへの依頼10、実装25、確認20、発表15、デプロイ準備確認10分。

## 要件を小さく書く

**要件**は「何ができるようになってほしいか」。今回は「たくさんのタスクから、名前の一部で探す」です。**受け入れ条件**は、完成したと判断するための具体的な条件です。

1. タスク名の一部を入力すると、その文字を含むものだけ表示する。
2. 検索欄を空にすると元の一覧に戻る。
3. 英字の大文字・小文字を区別せず、前後の空白を除く。
4. 「未完了」「完了」と検索を同時に使える。
5. 追加・編集・完了・削除・保存が引き続き使える。

検索対象は画面が読み込んだタスクです。Supabase版は最新200件なので、それより古いデータまで検索する機能ではありません。

## AIへの依頼を具体的にする

AIはコードの案を出せますが、正しさは動作確認が必要です。目的、対象ファイル、守る条件、確認方法を一緒に伝えます。1回の依頼で変更を増やしすぎないことが、理解と修正を助けます。

```text
学習用のマイタスクに、タスク名の部分一致検索を追加してください。
対象は app/public/index.html と app/public/app.js です。
新しいライブラリ、DBの列、APIは追加しません。
空欄なら全件、英字の大小は区別せず、前後の空白は除きます。
既存の状態フィルターと組み合わせてください。
visibleTasks() を使い、変更理由と確認手順を初心者向けに説明してください。
まず変更案を示し、変更箇所がわかる形でコードを提示してください。
```

AIチャットだけを使う場合は、必要な2ファイルの内容を貼り、出力を手で反映します。コード編集機能を使う場合も、変更差分（変更前と後の違い）を読みます。`.env`、パスワード、トークンは渡しません。

## 確認結果を次の依頼につなげる

「動きません」だけでなく、「未完了を選択後に『API』を入力した。期待は未完了1件、実際は完了も表示された」と伝えます。再現手順、期待、実際の3点があると原因を絞れます。

## 発表する

2分で「誰のどんな困りごと」「変更した場所」「確認した結果」「まだできないこと」を話します。コードの行数や見た目だけでなく、変更を説明できることを評価します。[評価表](../assessment.md)

最後の10分で[Cloud Runの事前準備](../cloud-run.md)を読み、第5回に使うプロジェクト・権限・公開するコードを確認します。第5回までにクラウド準備を終えます。[GitHub手順](../github.md)はコード共有の補助資料で、Cloud Runへの配置とは別操作です。
