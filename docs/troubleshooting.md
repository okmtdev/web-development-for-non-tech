# 困ったときの確認表

[教材の入口](../README.md)

最初に「どの操作で」「何を期待して」「実際は何が出たか」を記録します。秘密を消した最初のエラーメッセージを読み、同じ操作を1回ずつ試します。

| 現象 | 確認・対処 | 戻ったと判断する結果 |
| --- | --- | --- |
| nodeが見つからない | Node.js 24をインストール後、ターミナルを開き直す。必要ならPC再起動 | `node --version` がv24.x |
| PowerShellでnpm.ps1を実行できない | 組織のポリシーを変更せず `npm.cmd start` を使う | 起動URLが出る |
| package.jsonがないというエラー | ターミナルの場所を確認し、教材のルートへ移動 | ファイル一覧にpackage.json |
| ポートが使用中 | 起動済みのターミナルをCtrl+Cで止める。必要なら.envに `PORT=3001` | 表示されたURLで画面が開く |
| ブラウザが接続できない | `npm start` が動いているか、httpか、ポート番号が合うか確認 | `/api/health` がokを返す |
| HTMLを開いても追加できない | `file://` ではなく `http://localhost:3000` を開く | タスク追加が成功 |
| 画面を変更したのに変わらない | 保存と編集フォルダを確認して再読み込み | 見出しや色が変わる |
| .env変更が反映されない | サーバーを停止して再起動。.env.txtになっていないか確認 | 画面のモード表示が変わる |
| 追加したのに見えない | 状態を「すべて」、検索を空にして一覧再読み込み | 対象タスクが出る |
| ローカル保存が500になる | tasks.jsonが有効なJSONか、フォルダに書込権限があるか確認 | 追加・再読み込みが成功 |
| Supabaseモードにならない | APP_MODE、URL、publishableキーの設定を確認 | ログイン欄が出る |
| ログインが401 | 確認済みユーザーか、メール・パスワードが正しいか確認 | ログイン後に一覧が出る |
| 再読み込みでログアウト | この教材の仕様。トークンを永続保存しない | 再ログインでデータが戻る |
| Supabaseが502 | 一時停止からの復帰、通信、URL・キー・SQL実行先を確認 | 一覧と追加が成功 |
| 403／他人のデータが見える | schema.sqlのRLSと権限、キー種別を確認。RLSを無効にしない | A/B分離の確認が通る |
| SQLでalready exists | 既存の同名表がある。新規学習用プロジェクトを使う | 新しい表の作成が成功 |
| Cloud Runの起動が失敗 | APP_MODE=supabase、APP_ORIGIN=https、PORTを確認 | ログで起動とURLを確認 |

## ローカルデータが壊れた場合

サーバーを停止し、`app/data/tasks.json` を `tasks.backup.json` などへコピーして保管します。ファイルを修正できるならJSONの二重引用符・カンマ・括弧を確認します。架空データをすべてやり直してよければ元ファイルを別フォルダへ移動し、再起動して空の一覧から始めます。元データを確認せず削除しません。

## 相談用テンプレート

```text
環境：OS、node --version の結果、demo／supabase
操作：どの画面で何をしたか
期待：どうなってほしかったか
実際：画面の文言、番号、秘密を除いたエラー
直前の変更：ファイル名と変更内容
試したこと：1つずつ列挙
```

`.env`、ログイン時のNetwork本文、Authorizationヘッダー、パスワード、トークンは貼り付けません。
