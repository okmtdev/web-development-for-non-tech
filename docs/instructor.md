# 講師用ガイド

[カリキュラム](curriculum.md) / [スライド](../slides/README.md)

## 開講前

- 受講者を未経験の社会人、5回各90分と仮定しています。PC利用条件と実際の経験を確認し、事前準備30〜45分を案内。
- 教材のローカル版を配布するか、レビュー後にGitHubへ反映。反映前のGitHub URLだけを配らない。
- Node.js 24で `npm run check` と `npm test` を実行。受講者と同じコマンドで起動。
- 各回は説明より演習に時間を使う。用語は登場したときだけ説明し、コードの全行説明はしない。
- 第3回の前日までにSupabaseの稼働・Freeプラン・利用権限を確認。練習用A/Bで `npm run test:supabase` を実行しておく。
- 第5回前にクラウド準備45〜60分を別枠で案内。請求先、管理者の許可、ビルド用サービスアカウントの権限、学習用URLの公開可否を確認。講師は同じ手順で事前リハーサルし、ビルド待ちの長さを把握する。
- 第4回はAIを使えない人にも[実装例](solutions/04-search.md)を配布できるよう準備。
- スライドの演習ページでは投影を止めず、対象Markdownの場所を示す。詳細操作はMarkdownで読む。

## 各回の進行と介入

| 回 | 講師が実演すること | よく起きること | 次へ進む条件 |
| --- | --- | --- | --- |
| 1 | 実画面とHTML/CSS/JSの対応、完了操作の前後、見出し変更、ブラウザ保存の実験 | 作業フォルダが違う、保存先を混同 | 自分のPCで追加・再表示、保存領域を区別 |
| 2 | Networkの1通信、空白POST | Networkを開く前に操作、Consoleの結果と画面の混同 | POST/201と不正入力400を記録 |
| 3 | SQL作成、ログイン、A/B切り替え | 無料プロジェクト停止、ユーザー未確認、キー違い | 保存と本人以外に見えないことを確認 |
| 4 | 要件の分割、AIの差分確認 | 変更を一度に増やす、成功例しか試さない | 検索の確認表と基本操作を通過 |
| 5 | 非公開配置、URL設定、公開、再配置 | IAMの403、APP_ORIGIN不一致、ビルド待ち | URL・401・A/B・別ブラウザ・再配置の表を通過 |

第1回は[図解教材](browser-and-frameworks.md)を使います。3ファイルを説明するときは画面の該当箇所を指し、React／Next.jsの比較は5分に収めます。JSXの書き方やRSCの実装は求めず、「ブラウザにはHTML・CSS・JSなどが届く」を確認します。ブラウザ保存の説明では、タスクの正本・画面のコピー・ログイントークンを区別します。

## 進行が遅れた場合

第1回でインストールに15分以上かかる場合は、講師またはペアの画面で操作を分担し、個別セットアップは授業後へ。原因と未達項目を記録します。

第3回で登録・組織権限に阻まれた場合は、講師の練習用環境でDBとA/Bの挙動を観察し、本人はdemoで第4回を続けます。クラウド接続と本人のRLS確認は未完了として、補講30分を設定します。無理に有料プランへ移行しません。

第4回は検索の部分一致だけを最初に作り、次に大小文字、空白、状態フィルターを確認します。実装例を写した場合でも「なぜこの条件が必要か」を説明してもらいます。

第5回はビルド待ちに構成図の説明を行います。完了しない場合は補講30〜45分を確保し、再配置と保存確認を省略しません。公開が組織規定で認められない場合は、許可された講師環境で実習します。見学だけの受講者は配置操作を未達成として記録します。

## 講師の確認質問

「そのデータはどこにある？」「画面以外から同じAPIを呼んだら？」「AのIDをBが指定したら？」「何を試せば、できたとわかる？」を使います。答えが出ないときは、コードではなく入力・処理・保存の図に戻ります。

## 終了時

[評価表](assessment.md)を使って機能・説明・デプロイを確認します。第5回の[Cloud Run操作手順](cloud-run.md)で学習用URLを扱い、終了後の削除対象または管理期限を記録します。授業での公開確認は、継続的な本番運用の準備完了を意味しません。[GitHub手順](github.md)はコード共有の補助資料です。
